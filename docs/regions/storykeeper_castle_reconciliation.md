# Storykeeper Castle — Reconciliation of the SC Build with the Upgrade Roadmap

**Written 2026-09-08.** Read `docs/regions/storykeeper_castle.md` first;
this document is only useful next to it.

## 1. Why this document exists

Two roadmaps now describe Storykeeper Castle and they do not describe the
same castle.

- `docs/STORYKEEPER_CASTLE_3D_ROADMAP.md` (SC-0 to SC-11) was built. SC-0
  through SC-10 are implemented and SC-11's gate does not pass.
- `docs/regions/storykeeper_castle.md` (the upgrade roadmap, its own Phases
  0 to 14) is new, and its section 1 names the *result* of the SC build as
  the thing to fix: "transform Storykeeper Castle from a mostly static 3D
  walkthrough into the narrative heart of Learning Adventure Island."

That is a re-scope, not a continuation, and pretending otherwise would put
the next phase of work on a foundation that was built to answer a different
question. This document establishes, with measurements rather than
impressions:

- what the SC build actually produced;
- which of the upgrade roadmap's 14 phases that work satisfies, partly
  satisfies, or does not touch;
- which SC decisions survive the re-scope and which have to be re-opened;
- what the honest first phase is.

It records findings and a recommendation. It does not authorise any of the
work in section 7, which needs an explicit decision.

## 2. The finding that matters most

**No asset in this project has a texture.** That is not a figure of speech.
Every file in `public/models/` is generated by
`scripts/generate-world-assets.ts` from box, cone, cylinder, torus and
hex-prism primitives with flat `baseColorFactor` materials.

Measured across the whole pack on 2026-09-08:

| Measure | Value |
| --- | --- |
| `.gltf` files in `public/models/` | 108 |
| files with a texture or image reference | **0** |
| files with at least one animation clip | 7 |
| total meshes across the pack | 279 |
| mean meshes per asset | 2.6 |
| Keeper Quill (`npc-quill.gltf`) | 5 meshes, 6 clips, 0 textures, 16 KB |

The upgrade roadmap's section 4 asks for "stylized fantasy, low-poly to
moderate-poly, warm and colorful, exaggerated silhouettes, slightly
magical, Roblox / Prodigy / animated-adventure feeling." A 2.6-mesh
untextured primitive assembly is not a weak version of that target. It is a
different category of artefact: a legible grey-box prototype, which is what
the generator's own header says it is, in as many words - "there is no
artist and no 3D modeling tool in this environment."

This is the reason the castle cannot be put in front of a child today, and
it is upstream of every other gap in this document. A Castle Director
choosing ambient events, an NPC with Polly speech and a Trophy Room full of
artifacts, all rendered in untextured boxes, produce a more sophisticated
grey-box.

## 3. The two floor plans do not overlap

The SC build authored eight rooms in
`src/features/island-map/three/storykeeperCastleRegion.ts`. The upgrade
roadmap's section 6 names nine. **One room is common to both.**

| SC build (implemented) | Upgrade roadmap section 6 |
| --- | --- |
| `entry-hall` | 6.1 Grand Hall |
| `story-hall` | 6.2 Grand Library ⟷ `great-library` |
| `character-gallery` | 6.3 Hall of Heroes |
| `costume-room` | 6.4 Trophy / Artifact Room |
| `east-corridor` | 6.5 Observatory |
| `setting-tower` | 6.6 Inventor's Workshop |
| `illustration-studio` | 6.7 Potion Laboratory |
| **`great-library`** | 6.8 Forgotten Dungeon |
| | 6.9 Map Room |

`character-gallery` and 6.3 Hall of Heroes are close in spirit - both are a
wall of portraits - but they are not the same room: the gallery's portraits
are the `choose-hero` step's options, bound to the adventure engine, while
the Hall of Heroes is a *record of completed stories*, which is a
progression display driven by data that does not exist yet.

The deeper divergence is premise. The upgrade roadmap's section 2 - the
damaged Great Storybook, scattered pages, escaped characters, darkened
wings, and the five-rank ladder from Story Explorer to Master Storykeeper -
appears nowhere in the codebase, in any form. The SC castle's premise is
"Keeper Quill helps you make a story," which is the premise of the existing
`the-storykeepers-tale` adventure it was built to stage.

## 4. Phase-by-phase reconciliation

Status key: **Done**, **Partial**, **Absent**. "Partial" means real,
tested, load-bearing code exists that a full implementation would build on
rather than replace.

| Phase | Status | What exists today |
| --- | --- | --- |
| **0** Architecture decision | **Partial** | The castle/story boundary is settled and is the strongest thing here: ADR-019 gives the Story Engine sole ownership of progress, so a chapter played inside a 3D region writes one progress record. Absent: castle event schema, `ChildCastleProgress` schema, Castle Director schema, voice architecture. |
| **1** Asset pipeline | **Partial** | `assets/manifest.ts` (typed registry, id-resolved, no hard-coded URLs), `assetLoader.ts`, `gltfAssembler.ts`, `docs/THREE_WORLD_ASSET_CONVENTIONS.md` (units, pivots, colliders, interaction anchors, animation vocabulary, LOD, instancing). Absent: any texture path, Draco/Meshopt/KTX2, Blender export rules, an asset licence ledger, and any third-party kit. The registry lacks the doc's `version`, `preload priority`, `scale` and `interaction points` fields. |
| **2** Grand Hall vertical slice | **Partial** | The mechanics are all real - `firstPersonController.ts`, derived wall colliders, interaction raycast, Keeper Quill with six clips, doors. But it is the SC floor plan, not a Grand Hall; there is no Great Storybook and no artifact pedestal. |
| **3** Library vertical slice | **Partial** | The strongest SC work maps here. `great-library` has bookshelves, the book that slides onto a visibly empty shelf (SC-6), the sliding-bookshelf secret door and pattern lock (SC-9 beat 10), and three clues as separate finds (SC-8). Physical story discovery launching the same chapter as the normal interface is **done** and is exactly this phase's exit criterion. Absent: portal book, floating-book event, Lost Story Page. |

| **5** Amazon Polly | **Absent** | **Nothing.** No Polly, no S3 audio, no MP3, no `AudioListener`, no `PositionalAudio`, no `speechSynthesis`, no subtitles. The castle is completely silent, as is the whole island. Six sections of the upgrade roadmap (17-22) have zero corresponding lines of code. |
| **6** NPC framework | **Partial, and better than expected** | `src/features/npc/` is a real framework: `types.ts`, `dialogue.ts`, `conditions.ts`, `relationship.ts`, `memory.ts`, `questGiver.ts`, `schedule.ts`, all tested, with `content/islandNpcs.ts` authoring Keeper Quill, Pirate Pip and Bolt as multi-node conditional dialogue trees. `npcApproachBridge.ts` wires it into the 3D region. | **7** AI NPC dialogue | **Partial** | `generateCompanionTurn` and `generateTutorTurn` are live against Bedrock, with bounded context, structured schema validation, content checks, `AIInteractionAudit` rows and authored fallbacks. **5 pass, 4 partial, 5 fail.** The five failures are the five that produce
the feeling the roadmap is aiming at: *"I wonder what changed in the castle
today?"*

### Against section 43's first milestone

The upgrade roadmap names an exact 15-item slice as the thing to build
first. Of those 15, **two exist** (the first-person shell that a Grand Hall
would occupy, and library book-to-chapter discovery). Ember, the Great
Storybook, the portal book, the dragon quest, the artifact, the Trophy Room
pedestal, the Lost Story Page, the three ambient events, Polly, S3 caching,
AI Storykeeper dialogue and director-on-entry are all absent.

The SC-0 to SC-10 build is therefore **not a partial completion of this
milestone**. It is a different, well-executed slice.

## 5. What survives the re-scope

This is the part worth protecting. The re-scope invalidates the SC content
and art, not its engineering. These hold regardless of what happens next:

- **The engine-untouched constraint and its bindings.**
  `castleChoiceBindings.ts` maps entity ids to option ids the content
  already owns, so a physical interaction resolves to the same step a card
  drives. Ten phases of 3D work changed no adventure step, no story scene
  kind and no authored text. That property is why a re-scope is affordable
  at all.
- **HUD equivalence as an executable test.**
  `castleHudEquivalence.test.tsx` renders the real `AdventureStepCard` for
  every step staged as a world object and asserts each walkable option is
  on the card in the same words. It fails the day someone binds a step the
  card cannot answer. Any new room inherits this for free.
- **ADR-019.** One story-progress record regardless of entry point. This is
  the upgrade roadmap's section 16, already settled and already tested.
- **Derived wall colliders.** `buildWallSegments` derives walls from room
  floors minus archway gaps, so a doorway cannot be open on one side and
  sealed on the other. New rooms get this by construction.
- **The seating-puzzle factoring.** `createSeatingPuzzle` plus
  `seatedEntitiesToOrder` serve three separate beats as three instances of
  one mechanic.
- **The NPC framework and `ChildNpcState`.** Sections 13 and 14 of the
  upgrade roadmap are closer to done than any other system it describes.
- **The learning stack.** Curriculum, mastery, the director, deterministic
  grading, the hint ladder, and AI-proposes-engine-validates. Section 12's
  rule is not a change to make; it is the existing architecture.

## 6. What has to be re-opened

**The third-party asset decision, recorded 2026-08-28** in
`docs/STORYKEEPER_CASTLE_3D_ROADMAP.md` ("Third-party asset kits - not
yet"). That decision was correct on its own terms and its reasoning still
holds in part:

- texture-free is *load-bearing*, not aesthetic - no UV accessor and no
  image reference is exactly what lets `assetLoader.test.ts` run real
  `GLTFLoader.load()` calls inside jsdom;
- most of the SC castle is gameplay geometry, not scenery - a door with no
  handle, a shelf slot empty until `FIRST_STORY_TOLD`, three rods whose
  lengths are the graded answer, nine stars in rows of five and four. None
  of that is purchasable, because the geometry is the puzzle;
- state-variant pairs (`X` / `X-lit`) need identical vertices, which two
  downloaded models never have;
- CC-BY attribution and marketplace redistribution terms are real problems
  on a children's product.

**Two things have changed since it was written.** First, that decision set
its own revisit trigger - "**when to revisit: after SC-6**, and for scenery
only" - and SC-6 through SC-10 have all shipped, so the trigger has fired
by its own terms. Second, and more important, the bar moved. The old
decision was weighed against "what looks thin." The upgrade roadmap weighs
it against "showable to a child," and untextured primitives do not clear
that bar at any level of scenery polish.

The decision's own list of what an import would need is the honest cost,
and none of it exists today:

- scale normalisation to 1 unit = 1 metre;
- re-pivoting to ground-pivot (most packs are centre-pivoted);
- **either a texture-loading test path or a strip-textures-on-import step**;
- a licence ledger surfaced where a parent can find it.

The third bullet is the expensive one and it is not optional under the
upgrade roadmap, because stripping textures on import defeats the entire
purpose of importing. **A textured-asset test strategy is a prerequisite,
not a detail**, and it should be costed as its own piece of work before any
kit is downloaded.

The gameplay-bearing assets should stay generated regardless. That half of
the old decision survives intact and should be restated rather than
quietly dropped.

## 7. Recommended next phase

Not authorised - this needs an explicit decision. Recorded here so the
decision has something concrete to accept or reject.

**Do not start at the upgrade roadmap's Phase 0.** Its schema work
(sections 10, 11, 23, 24) is real but it is not the critical path, and
building a Castle Director for a castle nobody can look at optimises the
wrong constraint.

**Start with the art pipeline, scoped narrowly:**

1. **Decide the asset question** as its own ADR, with the four costs in
   section 6 priced. The output is a yes/no on third-party CC0 kits for
   scenery, plus a decision on whether the pipeline gains a texture path at
   all. Everything else waits on this.
2. **If yes: build the textured-asset test path first**, before importing
   anything. Today `assetLoader.test.ts` runs real `GLTFLoader.load()` in
   jsdom precisely because nothing has an image. Whatever replaces that has
   to be in place before the first textured file lands, or the pack becomes
   untestable in one commit and stays that way.
3. **Import scenery only, into one room**, and prove the manifest swap is a
   one-line change with no game-logic edit - which is the upgrade roadmap's
   own Phase 1 exit criterion, and something the current registry is
   already designed for.
4. **Then re-cost.** With one room actually looking like a castle, the
   remaining phases can be estimated against something real instead of
   against a grey-box.

**And run SC-11's two owed items regardless**, because they are cheap and
they gate everything: the Sprouts accessibility playtest, and a profiling
pass on a real tablet. The Great Library is the densest room on the island
and no frame of it has ever been rendered outside SwiftShader in a
container. Runbooks are in `docs/PILOT_READINESS.md` section 5b.

## 8. Decisions this document cannot make

1. **Third-party CC0 asset kits: yes or no**, and if yes, whether the
   pipeline gains a real texture path or strips on import. Blocks
   everything else.
2. **Which castle is being built** - the SC floor plan extended, or the
   upgrade roadmap's nine rooms. They share one room, so this is close to a
   restart of the region's content layer. The engine layer survives either
   way.
3. **The Great Storybook premise** - adopting it changes the castle's
   framing for every band, including SC-10's Sprouts content, which was
   authored against the current premise.
4. **Amazon Polly** - a new AWS service, a new cost line, an S3 audio
   bucket, and a voice-consent question for a children's product that
   `docs/PRIVACY_AND_SAFETY_REVIEW.md` has not been asked yet.
   `docs/IMPLEMENTATION_STATUS.md`'s "Decisions pending" already lists
   "text-to-speech provider and voice consent model" as open; the upgrade
   roadmap answers the provider half and not the consent half.
5. **Whether SC-11's gate still means anything** under the re-scope. It
   gates retiring the card-based route for a band. If the castle's content
   layer is being rebuilt, nothing should be retired for anyone, and the
   gate should be restated against the new target rather than left pointing
   at a castle that is being replaced.

## 9. How the numbers in this document were produced

- Asset audit: parsed all 108 files in `public/models/`, counting
  `images`/`textures`/`animations`/`meshes` per document.
- Absence claims: case-insensitive recursive grep over `src/`, `amplify/`
  and `scripts/` for each system's identifiers. "Absent" means no match,
  not "no match in the obvious place."
- Room list: `storykeeperCastleRegion.ts` room ids.
- Phase statuses: read against
  `docs/regions/storykeeper_castle.md` section 39's stated deliverables and
  exit criteria, not against its section titles.
