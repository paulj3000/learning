# Storykeeper Castle: Asset Manifest (SC-R02-07)

**Status:** reflects the repository as of SC-R02-06. ADR-028 (where the castle's art comes from) was
**accepted on 2026-11-03**, and it makes the current procedural art interim, so nothing here is a
production-art claim. The counts below were generated from
`STORYKEEPER_CASTLE_MANIFEST`, not typed by hand.

This document records what the castle actually draws, where each thing comes from, and what is
still missing. It adds no asset manager: every file is resolved through the existing registry
(`three/assets/manifest.ts`) and the Asset Library (ADR-030), and procedural art is declared in the
location manifest (`materials`, `surfaces`, `effects`, `BOX` scenery).

## 5. Adding an id

1. Add the entry to `three/assets/manifest.ts` with a kebab-case id (`castle-` prefix for
   castle-only decor), or declare procedural art in a `castleRooms/` module.
2. An imported file needs its archive SHA-256, licence and URL in `docs/ASSET_LICENCES.md` **before**
   it is committed.
3. A gameplay-bearing piece stays generated, with a state pair keeping identical vertices.
4. Never add a second registry, loader or manager. The Asset Library (Django) is the staff-facing
   store for published models (ADR-030); this repository's registry stays the runtime fallback.
