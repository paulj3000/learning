# Asset Licences

Every third-party file checked into this repository, where it came from, and
what its licence obliges us to do.

**ADR-020** ("Where the castle's art comes from", `docs/DECISIONS.md`) says
an asset licence ledger "becomes owed the moment any third-party file
lands". This is that ledger.

It was written when the first imported *models* landed, and writing it
turned up something worth recording plainly: **they were not the first
third-party files in this repository.** Two webfonts have shipped to users
since `d468e4c` (2026-09-05), correctly licensed and explained in a code
comment, but never entered in any ledger because no ledger existed. A
third-party reference image landed in `docs/` in the same restyle. The ledger below
covers everything, not only the models.

Assets **not** listed here are original to this project: the 108 `.gltf`
files generated by `scripts/generate-world-assets.ts`, `public/favicon.svg`,
and all authored code and copy.

## Fonts — shipped to users

| File | Source | Licence | Attribution owed |
| --- | --- | --- | --- |
| `public/fonts/lexend-variable-latin.woff2` | Lexend (variable, latin subset) | SIL Open Font License 1.1 | None in-product |
| `public/fonts/figtree-variable-latin.woff2` | Figtree (variable, latin subset) | SIL Open Font License 1.1 | None in-product |

Both are self-hosted deliberately rather than linked from Google's CDN: a
`<link>` to `fonts.googleapis.com` would make every page load of a
children's product issue a third-party request carrying the child's IP and
referrer. The reasoning is in `src/styles/fonts.css`, which is also where
the licence was recorded before this file existed.

OFL 1.1 permits redistribution and self-hosting, and requires no
user-facing attribution surface. Its one real constraint is that the fonts
may not be sold on their own and any derivative face must not use the
reserved name — neither of which this project does.

Lexend is not only a stylistic choice: it was designed to reduce visual
stress and is used in reading research with exactly this product's age
range.

### What CC0 means for this project

CC0 is a public-domain dedication: commercial use is permitted, no
attribution is required, and there is no obligation to surface a credit
anywhere a parent can reach. That is exactly why it was preferred.

ADR-020's rule is *"No CC-BY asset without an attribution surface a parent
can reach"*. **No such surface exists in the app today, and none is owed
while every import is CC0.** The moment a CC-BY asset is proposed, building
that surface is part of the cost of accepting it, not a follow-up.

Crediting Kay Lousberg anyway is welcome and costs nothing; it is a courtesy,
not a term.

## Where they are used

Both are Storykeeper Castle floor and ceiling slabs, registered in
`src/features/island-map/three/assets/manifest.ts` under the ids
`ground-tile-stone` and `ceiling-tile`, and placed by
`storykeeperCastleScene.ts`.

They were chosen as the first import because they need **no normalisation**:
both are authored as 4x4m slabs centred on x/z, which is already the
`SLAB_SIZE_METERS` grid the castle places on, and both are single-mesh with
one material, so they still go through `createInstancedMeshFromAsset`. The
only adjustment is a y offset for slab thickness, documented at
`FLOOR_SLAB_TOP_OFFSET` / `CEILING_SLAB_BOTTOM_OFFSET`.

The generated `ground-tile-stone.gltf` and `ceiling-tile.gltf` are still on
disk and still produced by the generator, so reverting the swap is two urls
in the manifest and two offsets in the scene.

### The three Kenney nature props

These take over the shared kit's `rock`, `foliage-tree` and
`foliage-tree-lod1` ids, so they appear wherever those are already placed:
Welcome Harbor, Pirate Builder Bay, Clockwork Harbor and the Dragon's
Sanctuary place `rock`; the first two and Wonderwild Forest place the tree.
No scene file changed - the swap is three manifest urls.

Unlike the KayKit slabs these **did** need normalising, and
`scripts/import-kenney-assets.ts` is that work, done reproducibly rather
than by hand: Kenney's castle kit is authored on a 1-unit module (its wall
is 1.00 x 1.31 x 1.00), each source file references a shared
`Textures/colormap.png` by relative uri, and the three kits do not share
one atlas. The importer downscales each model to fit inside the box of the
generated asset it replaces, bakes that scale into the vertices so the root
stays identity, and embeds the kit's own atlas as a `bufferView` so the
file is self-contained. `assets/kenneyImports.test.ts` pins all of it.

The generated `rock.gltf`, `foliage-tree.gltf` and `foliage-tree-lod1.gltf`
are still on disk, so reverting is three urls.

### The two Clockwork Harbor characters

`npc-harbor-master` and `npc-professor-ticktock` are placed by
`clockworkHarborScene.ts` at the two spots in `NPC_SPOTS`. Before this both
loaded `npc-pip`, so the Harbor Master and Professor Ticktock were the same
pirate as each other.

Like the KayKit slabs and unlike the Kenney scenery, these need **no scale
or pivot normalisation**: measured before use, both are ~1.86m and
ground-pivoted as authored, with a single root. They also carry **no
textures** - every material is a flat `baseColorFactor` - which is what
makes them sit beside the untextured generated kit rather than beside the
Kenney atlases.

What they needed was subtraction, and it is the licence-adjacent part worth
recording here: the source pack ships **24 clips per character, most of them
combat** (`Gun_Shoot`, `Sword_Slash`, `Punch_*`, `Kick_*`, `Death`,
`HitRecieve`). CC0 permits shipping them; this product's audience does not.
`scripts/import-character-assets.ts` removes them from the file rather than
leaving them unreferenced, keeps the three that map onto
`animationVocabulary.ts` (`Idle`, `Walk`, `Wave`), and prunes the orphaned
buffer data - 2797 accessors down to 402, 2.9 MB down to 824 KB.
`assets/characterImports.test.ts` is what stops a re-import putting them
back.

Nine of the eleven characters were **not** imported, listed with reasons in
the importer's `EXCLUDED` table. Two of those reasons are content ones
(`Swat`, `Punk`); the rest is simply that no named role is waiting.

## Adding a third-party file

This applies to **any** third-party file, not only a model - a font, an
icon, an audio clip and a reference image all belong in this ledger. The
fonts above went unledgered because the rule was read as being about art.
It is not.

Before checking one in:

1. **Prefer CC0.** A CC-BY asset costs an attribution surface (see above)
   and needs that surface built as part of the same change.
2. **Check the state-variant rule.** ADR-020: both halves of a state pair
   come from the same producer, or the construction-time swap visibly pops.
3. **Check it is not gameplay-bearing.** ADR-020 keeps the castle's 44
   gameplay-bearing assets generated - where the geometry *is* the rule
   (rods graded by length, nine countable stars), it is not purchasable.
4. **Add a row to the table above**, with the retrieval date.
5. **Hold it to the import contract**, which is
   `describe('imported castle kit')` in `castleKit.test.ts`: grid fit, pivot,
   single-mesh where instanced, an embedded rather than external texture, and
   no required glTF extension.
6. **Prefer a self-contained `.glb`.** A file referencing its texture by URI
   needs a second file placed beside it, and 404s the moment one moves and
   the other does not.
