## 2. Draft ADR (number to reserve on `main`)

**ADR-NNN: The Game Engine Core is a capability-composed runtime in `game/`; movement writes one
canonical player transform; the engine emits versioned gameplay claims and never scores.**

- **Context.** ADR-020 named `game/` and the engine boundary but left the runtime shape, the
  extension model and the scoring interface open (LAI-2003). Five realm branches each grew
  their own wiring around one shared controller.
- **Decision.** (1) One runtime: lifecycle, fixed-timestep simulation, entities and systems,
  typed bus, scoped disposal, service ports, diagnostics. (2) Behaviour is added by validated,
  versioned capabilities; jumping is one of them. (3) Movement alone writes the canonical
  `PlayerTransform`. (4) Collision is the existing AABB model behind a `PhysicsProvider` port.
  (5) Gameplay claims `lai.gameplay-event` v1 are the only progress-relevant output; Django
  confirms them. (6) Realms and adventures consume the engine through the SDK definitions.
- **Consequences.** Realms migrate by data; one place to fix movement bugs; scoring has a
  stable intake; temporary duplication (platform math, atmosphere) until GE-076.
- **Alternatives.** Keep growing `createLocationEngine` (rejected: one 1679-line file edited by
  every realm). A physics library (rejected without an ADR). A class hierarchy per world type
  (rejected: composition is easier to test and configure).
