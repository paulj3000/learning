| GE-L6 | Resolved: chests emit no discovery claim. The chest claim is `learning.answer.submitted` with a `CHEST_CHALLENGE` learning ref, through `ChestsApi.submitAnswer` (agreed with the scoring lead; replay chests too, server records practice) | Closed |
| GE-L7 | Platforms default to `route: REQUIRED`, so moving and falling platforms must be marked OPTIONAL explicitly or validation fails | Intended (jumping standard); documented for authors |

| GE-L9 | `renderer.info` gauges, the WebGL path and production-build route stripping are untested in unit tests | Merge readiness (GE-090) |
| GE-L10 | Closed 2026-11-19. In the standard assembly, platform carry is applied after the platforms system, so the canonical transform showed the carried position one simulation step (about 16 ms) later than the controller. Order traced: movement (-100) writes the transform, platforms (-10) move, carry (10) moves the controller. Fix: the movement system (still the single writer) exposes `syncTransform()`, and the carry system calls it after a carry or launch. Position, grounded, state and support follow; `previousPosition` stays the step start (interpolation includes the carry); `velocity` stays the child's own, so a carried child keeps an idle gait and facing. Carry stays collision-tested (no tunnelling) and moves at most the platform's own step (no teleport) | Closed. | GE-L11 | Locations without an adventure or companion claim binding drop the GE-067 host claims (discoveries, NPC talks) and bridge checkpoint claims, because `emitLocationClaim` needs a visit binding (found by the Storykeeper lead) | Fixed: `ThreeLocationWorldView` sets a default location-visit binding (realmId and `explore:<slug>` from the Place slug, areaId the region, no session); a companion binding overrides it; no adventure start or completion is claimed under it (shape agreed with the scoring lead) |
| GE-S1 | The 10 legacy island-map shims import through the package `./*` wildcard (`@lai/game-engine/movement/firstPersonController`) rather than a listed subpath (`./movement`, `./camera`, `./input`) | Closed 2026-11-22 (GE-076 item 2, branch `fix/GE-S1-import-shims`). | GE-L12 | `createStandardEngine`: a dispose during async setup resolves with an already-disposed handle instead of rejecting (the "disposed while starting" throw is unreachable); the runtime is clean (zero resources, avatar removed) | Low. | GE-L13 | `CheckpointsService.markReached` on an older checkpoint after a newer one makes the older one `latest()` again | Low. | GE-T1 | Closed 2026-11-19. Three host-lifecycle stabilization tests (20-cycle remounts, keyboard retry) had a 30 s budget raised to absorb machine load, against TESTING_STRATEGY. Follow-up: the 20-cycle remount test still timed out once at 5 s in a gated set; cut to 6 cycles (a per-cycle leak shows from the second), passing gated | Closed |
| GE-T2 | `GameHost.test.tsx` costs about 1 s per test, and its retry test failed at the 5 s default (once in a gated set, 2 of 3 gated alone, 2026-11-19). **Root cause found: host timer latency, not test code.** The development host is a VirtualBox guest (`systemd-detect-virt`: `oracle`). A 10 ms `setTimeout` takes 0.4 to 1.9 s about half the time, in plain Node outside Vitest, in Vitest's node and jsdom environments, and in Python's `time.sleep`. The thread is idle meanwhile (a CPU profile of the file is 60% idle). The guest's `/proc/stat` reads 99.8% idle while processes are busy, so the gate's load figures do not see these stalls. Every Testing Library `waitFor` poll and every test timer can therefore wait about 1 s, which explains this file and the GE-D9 class | Medium (environment, not product). Not fixable in test code without removing real timer waits. Do not raise budgets. Classify a 5 s timeout whose test passes alone as this host latency only after a timer probe shows it. Owner decision: a host without VM timer stalls (VirtualBox timer and paravirtualisation settings, or a non-VM runner) for merge-readiness runs. Re-investigated 2026-11-19 (Wave 2 stabilization): `GameHost.test.tsx` alone, 3 gated runs, 10 of 10 each, test time 0.24 to 0.40 s per file; the gate recorded timer stalls in 2 of 3 runs (up to 366 ms) with no failure. Lifecycle audit of `useEngineRuntime`: the frame loop is cancelled on teardown and cannot restart after it, window and document listeners are removed, the async start is guarded (`cancelled`, `disposed`), runtime and renderer are disposed; the stabilization tests pin this with a deterministic frame fake (one pending loop, zero after unmount, dispose exactly once, no ready after unmount while starting). A deadlock would fail every run; the observed failures pass alone and coincide with stalls. **Classified environmental, not code.** Confirmed 2026-11-21 on a host without VM timer stalls: EC2 full-unit run 44927511735 ran 6343 React tests with 0 timeouts (GameHost and about 187 parity tests included). Closing the B15 card ([ijhrYTi4](https://trello.com/c/ijhrYTi4)) is the owner's call |
| GE-L14 | Telegraph part closed 2026-11-19: an optional host `groundHeightAt(x, z)` (the engine's existing signature) drapes the outline and fill over sloped and uneven ground, re-drapes the shrinking fill at its scale, and lands the object on the ground; without it the flat y 0.03 telegraph is unchanged. The live island-map host has no ground query yet, so live Areas stay flat until it provides one (flat ground today: Firepeak). Was: bridge presentation assumes flat ground: the telegraph sits at y 0.03 and the falling object drops from 6 m. Weather part closed 2026-11-19: `environment.weather` `area` with `FOLLOW_PLAYER` keeps precipitation round the child (North Pole); the default stays a 25 m box at the start. The bridge also takes the host render quality (LOW draws no weather or particles, as the Area atmosphere), and the weather view shares the tier budget only across the kinds falling now (an unused built-in RAIN no longer takes half) | Closed in the engine. Remaining for a terrain Area: the host implements `groundHeightAt` (owner of `createLocationEngine`). Rechecked 2026-11-21 on `main`: no island-map host implements it (`bridgeHost.ts` declares it optional); P2, Agent 4, when a terrain Area is scheduled. Tests: 4 bridge tests (flat fallback, slope, bumps with fill re-drape, null and non-finite) |
| GE-L15 | Closed 2026-11-19. A spinning (turntable) engine platform's mesh did not rotate: the simulation kept the yaw, but presentation never read it. Also found: the carry was the tangential velocity times dt, which pushed a still child outwards about 1 m a minute at 45 degrees a second, off the edge in time. Fix: `PlatformsApi.yawOf(id)`, the bridge sets `mesh.rotation.y` (the model is a child of the mesh), and the carry is the exact chord of each step's turn | Closed.
